# Recovered §9.2 tables (and one §9.3 CDF)

This directory materializes the tables that the core-table audit
(`docs/spec-audit/12-tables-core.md`) found **absent from `spec/tables/`**.
It is spec-only: no encoder path is changed here, and the headers are not
included by the root build. Everything is extracted from the pinned PDF
`spec/AV2_Spec_v1.0.0.pdf` (SHA-256 `e9916f09…b533f`, AV2 v1.0.0,
commit `38f28e7`).

`value_sha256` in `missing_tables_provenance.h` is the SHA-256 of the
canonical JSON value list. It pins the **extraction**, not just the emitted
header bytes, so a changed PDF or a changed parser is caught even if the header
would otherwise still compile.

## Values worth calling out

- `Mode_To_Txfm` is printed as TX_TYPE **names**, not numbers. The generator
  maps them through `spec/tables/constants.json` (`DCT_DCT=0 … H_FLIPADST=15`)
  and keeps the names in `kModeToTxfmNames`. Values:
  `DCT_DCT, ADST_DCT, DCT_ADST, DCT_DCT, ADST_ADST, ADST_DCT, DCT_ADST,
  DCT_ADST, ADST_DCT, ADST_ADST, ADST_DCT, DCT_ADST, ADST_ADST, DCT_DCT`.
- `Side_Thresholds` starts with 57 entries of `-16`, then ramps from `-14` to
  `1678`; the parser drops four prose lines interleaved by the PDF's two-column
  layout but the count and every value match the local copy.
- `Gaussian_Sequence[0] = 56`, `[2047] = -484`, range `[-1752, 1688]`, every
  entry a multiple of 4.
- `Tile_*_Scaling_Factor`: seq_level_idx `0..21` are numeric; `22..30` are the
  literal token `reserved` in the PDF and are encoded as
  `kReservedTileScalingFactor = -1`. **This corrects the comment in
  `src/bitstream/m0_headers.cpp:81` that assumed 4 for every entry.** The M0
  configuration's level has `(4, 4)`; the `-1` entries are reserved
  `seq_level_idx` values, not the M0 level.
- `Default_Use_Most_Probable_Precision_Cdf` rows are
  `{20650, 31, 0}`, `{15758, 31, 0}`, `{4571, 31, 0}`.

## Algorithmic vs tabulated

All 13 tables are **tabulated** in the pinned PDF; none had to be
reconstructed from an algorithm. In particular `Gaussian_Sequence` is a literal
`[2048]` initializer (it is not generated by running the grain RNG at build
time), and `Dr_Intra_Derivative` is a literal integer table (do not recompute
it from `tan()` or a reciprocal; `src/encoder/ibp/ibp_tables.h` already warns
about this).

The *local consumers* of `Tile_Width_Scaling_Factor` /
`Tile_Area_Scaling_Factor` are algorithmic: `level_tile_limits()` and
`level_factors()` derive the values from `seq_level_idx` thresholds rather than
reading a table. Those algorithms currently agree with the PDF for levels
`0..21`, and both already treat `>= 22` as reserved. The generated tables make
that agreement testable.

## Cross-checks

The generator compares the PDF extraction against every local copy it can find
and **fails the run on any disagreement** rather than choosing one:

| Table | Local source(s) |
|---|---|
| `Side_Thresholds`, `Q_First`, `W_Mult`, `Q_Thresh_Mults` | `filters/deblock/deblock_core.h` |
| `Wedge_Bits` | `inter/advanced/tables/wedge_tables.h` |
| `Palette_Color_Context` | `palette/palette_core.h` |
| `Palette_Color_Hash_Multipliers` | `palette/palette_core.h` hash expression |
| `Gaussian_Sequence` | `filters/spec_tables/film_grain_tables.h` |
| `Dr_Intra_Derivative` | `intra_modes/intra_modes.cpp`, `mrl/mrl.cpp`, `mrl/mrl_test.cpp`, `ibp/ibp_tables.h`, `cuda/intra_modes/intra_modes.h` |
| `Default_Use_Most_Probable_Precision_Cdf` | `spec/tables/default_cdf.json` |
| `Tile_Width/Area_Scaling_Factor` | `tiles/tile_layout.cpp` at test time (`level_tile_limits`) |

Current result: **all cross-checks agree; no disagreements to report.**
`Mode_To_Txfm` has no local equivalent. The §9.3 JSON does contain
`Default_Use_Most_Probable_Precision_Cdf` with the same values, but no generated
C++ binding existed, which is the gap this header fills. `Gaussian_Sequence`
has only one local copy in the tree (`filters/spec_tables/film_grain_tables.h`,
itself generated from the official attachment); there is no second hand copy to
compare against.

## Regenerating and testing

```sh
cd src/encoder/tables/missing
python3 generate_missing_tables.py            # rewrite the headers
python3 generate_missing_tables.py --check    # PDF pin + value pins + freshness
python3 generate_missing_tables.py --print-hashes
./build_and_test.sh                           # --check, then compile/run the test
```

`--check` fails on: a changed PDF, changed extents, a changed value digest, a
cross-check disagreement, or a stale/missing generated header. The test asserts
all dimensions as compile-time constants, checks sample and boundary values,
and compares every recovered array against the local copies listed above.

## Replacement notes

- `Palette_Color_Hash_Multipliers` is still an inlined expression
  (`scores[0] + 2 * scores[1] + 2 * scores[2]`). Replacing it with the table is
  a one-line change but would add an array lookup in a hot path; the
  cross-check is the low-risk option.
- `Gaussian_Sequence` already has a generated header from the official
  attachment (`filters/spec_tables/generate_spec_tables.py`). The §9.2
  extraction here is an independent PDF cross-check; do not keep two runtime
  copies.
- `Dr_Intra_Derivative` has five copies. The test oracle copy
  (`mrl/mrl_test.cpp`) should stay independent if the goal is an oracle; the
  other four can consume the generated table.
- The `Default_Use_Most_Probable_Precision_Cdf` binding belongs in the M2 CDF
  set (`m2_cdf_tables.h`) alongside `Default_Pb_Mv_Precision_Cdf`; this header
  is the standalone source until that integration happens.
