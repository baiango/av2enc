# CUDA full-trellis RDOQ (`src/cuda/rdoq/`)

GPU batch kernel for the full coefficient-level RDOQ trellis in
`src/encoder/rdoq/`. It is **not wired** into the M1 GPU pipeline and does not
change any bitstream. The CPU implementation remains the reference.

## Status

The kernel is written for `sm_86` and has a CPU-vs-GPU parity test, but this
checkout was produced on macOS without `nvcc` or a CUDA device, so **it has not
been compiled or run here**. The parity test must be run on the 3060 box:

```sh
cd src/cuda/rdoq
./build_rdoq_batch_test.sh                 # sm_86
CUDA_ARCH=sm_86 ./build_rdoq_batch_test.sh
```

The CPU component's own tests and the real-M1 measurement do not need CUDA and
are run by `src/encoder/rdoq/build_and_test.sh`.

## Model: caller-supplied rate table

The device DP must not call a transcendental or a host callback. Instead the
caller supplies a precomputed rate table. For one job:

```
S = prev_level_cap + 1
L = table_levels                       // bound[i] <= L - 1
normal rate index(i, s, m) = table_offset + (i * S + s) * L + m
eob    rate index(i, s, m) = same layout in eob_rate
block EOB rate index(e)    = eob_table_offset + e,  e = 0..N
path storage               = path_offset + i * S + s
```

`bound[i]` is the same value `av2enc::rdoq::rdoq_level_bound()` returns on the
host (derived bound plus the 64-level margin, or the caller's `level_cap`), and
the kernel uses the same safe distortion stop rule as the CPU, so both search
the same levels even for a non-monotone rate table. `sign[i]` is
`+1/-1` per coefficient (for `original == 0`, use the scalar level's sign, as
the CPU does). The table may be generated by the AV2 CDF model, a measured
table, or an exact entropy probe; the kernel only reads it.

The test builds the table with a deterministic host model, runs the CPU
`rdoq_quantize()` with a callback that reads the same table, and compares
levels, EOB, rate and cost against the device result. That isolates DP and
floating-point parity from the rate model.

## API

```cpp
namespace av2enc::cuda::rdoq {

struct BlockJob {
  int32_t coefficient_offset, num_coefficients, level_offset, path_offset;
  int32_t table_offset, eob_table_offset;
  int32_t prev_level_cap, table_levels;
  double quant_step, lambda;
};

struct Batch {
  const double* original;
  const int32_t* sign;
  const int32_t* bound;
  const double* normal_rate;
  const double* eob_rate;
  const double* block_eob_rate;
  const BlockJob* jobs;
  int32_t num_jobs;
  int32_t* levels, *eob;
  double *distortion, *rate_bits, *cost;
  int32_t* status;
  int32_t* path_levels;
  uint8_t* path_modes;
};

cudaError_t quantize_batch(const Batch&, cudaStream_t);
}
```

All buffers are caller-owned. The launcher allocates/frees nothing and never
synchronizes. `path_levels`/`path_modes` need `num_coefficients * S` entries per
job; put long-lived scratch in the arena. `status[i]` is 0 on success and -1 on
a rejected job (also `eob[i] = -1`).

## Numeric contract

* CPU reference: `src/encoder/rdoq/rdoq.cpp`, built with `-ffp-contract=off`.
* Device build: `-fmad=false`.
* Same DP recurrence, same tie-break order, same safe distortion stop rule,
  same final cost recomputation.
* One thread per block. The DP state arrays are local (`kMaxStates = 64`);
  path storage is global scratch. This is a correctness-first kernel, not a
  tuned one.

At video scale the right design is a device-side rate model or a per-block
cost table generated in a cheap prepass, plus warp-level batching of blocks
with the same transform size. The current table layout is deliberately simple
and generic; it is not sized for a whole 1080p frame of high levels.

## Integration notes

1. The TX stage already has the unquantised coefficients. Generate `bound` and
   `sign` on the host (or a small device prepass) with the same rules as the
   CPU core.
2. Build `normal_rate`/`eob_rate`/`block_eob_rate` from the entropy model. The
   entropy owner owns that model; this component does not.
3. Run the kernel after forward TX and before inverse TX/reconstruction.
   Levels are written in scan order, which is what the §8.3 stream expects.
4. Compare CPU and GPU decisions on the same block batch before letting the GPU
   result drive the bitstream. Run `tools/validate_dav2d.sh` after wiring.
5. No `cudaMalloc` in the frame loop; use the arena and the explicit stream.
