# Test media: provenance and licensing

Status: **remediated for the gate fixtures.** CI is clean, the still/video gate
fixtures are NASA-derived public-domain media, and the retired promo-derived
clips are no longer referenced by any tracked file. The only remaining
unapproved input is the legacy `dav2d_smoke` stream, which has its own note
below.

## Policy

1. CI and committed tests must not depend on copyrighted media. The workflow in
   `.github/workflows/ci.yml` generates its input with ffmpeg `testsrc2`; it
   never downloads or ships a clip.
2. `testdata/` is gitignored and local-only. Nothing in it is redistributed, but
   "local only" is not a licence: fixtures derived from copyrighted video must
   not be used for tests either.
3. A new fixture is allowed only if its source and licence are recorded here and
   it can be regenerated by a documented command.

## Regenerating the approved fixtures

The NASA-derived gate fixtures are generated by one script, which records every
seek offset, crop and filter. Run it from a checkout with a real (not
symlinked) `testdata/`:

```sh
tools/make_testdata_pub.sh          # writes testdata/pub_*.y4m
tools/make_testdata_pub.sh --check  # regenerates to a temp dir and diffs
```

The KPI fixtures predate the script and are reproduced here for completeness:

```sh
SPACE=First-8K-Video-from-Space_orig.mp4

# 240p KPI clip (matches the pin set)
ffmpeg -ss 10 -i "$SPACE" \
  -vf "fps=30,scale=480:240:in_range=full:out_range=limited" \
  -frames:v 60 -pix_fmt yuv420p -an -f yuv4mpegpipe nasa_480x240_30fps_60f.y4m -y

# 720p KPI clip
ffmpeg -ss 10 -i "$SPACE" \
  -vf "fps=60,scale=1440:720:in_range=full:out_range=limited" \
  -frames:v 60 -pix_fmt yuv420p -an -f yuv4mpegpipe nasa_1440x720_60f.y4m -y

# 720p real-detail recipe clip
ffmpeg -ss 20 -i "$SPACE" \
  -vf "scale=1440:720:flags=lanczos,fps=60,format=yuv420p" -frames:v 60 \
  -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  -f yuv4mpegpipe space8k_1440x720_60f.y4m -y
```

Design notes:

- The stills are **native-resolution crops**, not whole-frame downscales: a
  64x64 downscale of a 4K frame is so smooth that CDEF, loop restoration and
  GDF all become no-ops and their gates stop exercising the code. The three
  crop windows nest, so they show the same scene at three scales.
- Offsets were picked by measuring per-frame luma entropy at the target size
  over the whole clip; 305 s (training) and 55 s / 135 s (First-8K) are local
  maxima (0.98 / 0.93).
- The training source is limited-range H.264, so its range map is the identity
  (`in_range=limited:out_range=limited`); the First-8K source is `yuvj420p`
  and needs `in_range=full:out_range=limited`, matching the KPI clips.
- `pub_640x360_4f` is 30 fps, not 60: the source is 29.97 fps, and four real
  frames keep the motion/ref-MV gates active. A 60 fps conversion would
  duplicate frames and make them inert. Its offset (545 s) differs from the
  stills (305 s): the same-reference-compound and IST gates need a window where
  both tools are actually selected (13 same-ref leaves and 2 IST blocks at
  545 s; 0 and 0 at 305 s).
- ffmpeg version and filter flags are part of the fixture identity: a different
  `scale` implementation produces different bytes, and every byte-pinned gate
  depends on the exact output.

## Rebaselining rules

When a fixture changes, only numeric pin constants may move: IVF bytes, md5,
per-section byte sizes and content-describing counts that the gate prints as an
observation (leaf/block counts). Structural assertions, thresholds,
`>=`/`<=` invariants, rejection checks and tree-shape checks must stay as they
are. The KPI pins (`25,009 a1d0dba1`, `25,141 3984677b`, `23,690 1b99127a`,
`24,113 7f03eb6e`, 720p `36,572 c4ba2813`) are derived from the approved NASA
fixtures and must never move because of a gate-fixture swap.
