# GPU coverage and arena compliance — per-tool matrix

Generated by `tools/gpu_coverage/inventory.py` from the tree. Code and
tests were read; the GPU was **not** run and nothing was compiled. Status
lines in component READMEs are used only for the *real-GPU evidence*
column, and are labelled as documentation rather than as a measurement
performed here.

**Snapshot:** audit start at `debb00e`; document generated at git `7673295` with 122 `.cu` / 31 `.cuh`, 62 kernel TUs.
Ten GPU modules landed while the audit was running; the snapshot is the
contract. `--check` fails if
a curated path disappears, and any kernel TU that is not in the curated
list is auto-added so no `.cu` can go uncounted.

## Scope and vocabulary

| Verdict | Meaning |
|---|---|
| **GPU-SERIAL** | entropy, headers, syntax, CDF, metadata, conformance: CPU by design, no kernel required |
| **GPU-REQUIRED** | pixel/filter/transform/MC/prediction work: must have a GPU kernel and bit-exact parity |
| **GPU-MISSING** | required pixel work, no kernel exists |
| **GPU-UNWIRED** | kernel exists, but the M1/M2 GPU path rejects or never calls it |

`GPU-REQUIRED` says the work is device-resident on at least one GPU path;
the *wired* column names which one. The product build (`CMakeLists.txt`)
only links the **M1** GPU target. `src/cuda/pipeline/video/` is gate-only: there is no
`av2enc_video_gpu` target in `CMakeLists.txt`, so every M2 row is reachable
only through `src/cuda/pipeline/video/build_gpu_gate.sh`.

Inventory under `src/`:

- **122** `.cu` files, **31** `.cuh` files.
  Counts are recomputed from the tree on every run; the number moves when
  a component lands.
- **62** kernel translation units, **60** test/bench/gate translation units.
- Of the kernel TUs, **59** are under `src/cuda/` and **3** under other trees.
- The 26 feature rows in Matrix 1 are the component directories added
  after commit `19c5dd9` (inherited audit baseline) up to `debb00e`.
  They are marked with `†` in the matrix.

## What this means

1. The **serial half is clean**: all 23 header/syntax/metadata/conformance
   feature dirs are correctly CPU-side. They should not get kernels.
2. The **M1 pixel pipeline is complete and wired** for its declared scope
   (`plan`, `search`, `chroma`, `tx`, `recon`, `deblock`). Everything M1
   can signal is device-resident.
3. The **M1 filter surface is the largest unwired block**: CDEF, CCSO,
   loop restoration, DIP, IBP, MRL, palette, IBC, QM, HBD, MHCCP and the
   ten newly landed modules all have kernels and none is reachable through
   `--still-gpu`. The options are rejected by name, so this is a capability
   gap, not a silent fallback.
4. The **M2 pixel path is complete for its baseline** and byte-identical,
   but it is not in `CMakeLists.txt`; M2 is a gate, not a product.
5. The **video half landed during the audit but is 100% unwired**:
   `tip`, `tip_deblock`, `compound_full`, `morph`, `warp_stack`, `gdf`,
   `pc_wiener`, `intra_full`, `lossless_inter` and `tx_partition` all
   have arena-based kernels and no caller, and most have no parity test.
   Wiring plus tests, not new algorithms, is the remaining GPU work.
6. **Arena compliance is good in the hot paths and broken at the edges**:
   M0, M1, scheduler and the shared kernels are arena-owned. `ibc` and
   `high_bitdepth_gpu` were fixed during the audit. The M2 backend and the
   transform-stream adapter still allocate directly; the newer modules
   all implement `required_device_bytes()` and `mark()`/`rewind()`.
