# Minimal AV2 still-picture bitstream — field-by-field recipe

Scope: **M0**. One still picture, 8-bit 4:2:0, one tile, key frame, fixed 64x64
superblocks, 32x32 luma coding blocks, DC intra only, DCT 32x32 only, fixed QP,
no loop filters / film grain / SVC / palette / CfL / intrabc / IBC / segmentation /
delta-Q / QM.

Normative reference: `spec/AV2_Spec_v1.0.0.pdf` (AV2 v1.0.0, 2026-05-28, commit
38f28e7), SHA-256 `e9916f09…b533f`. Citations are clause numbers of that document.
Machine-readable tables referenced here live in `spec/tables/` and are generated by
`tools/spec_extract/`.

Anything I could not pin down is marked **TODO** and listed in
`docs/open-questions.md`.

---

## 0. Encoder-vs-decoder caveat

The specification defines **only the decoder**. `read_symbol()` (§8.2.6) tells you
how to consume bits; the matching range *encoder* must be derived as its inverse.
There is no normative pseudocode for writing. Consequences:

- The encoder must reproduce §8.2.6's arithmetic exactly, including
  `pp = ((f >> EC_PROB_SHIFT) << 4) + Prob_Inc[N-2][symbol]`, the `cur` recurrence,
  the renormalisation (`bits = 15 - FloorLog2(newRange)`) and the CDF update.
- `read_bool()` (§8.2.3) is a *separate* equiprobable path used by `L(n)` literals
  (`read_literal`, §8.2.5) and it shares `SymbolValue`/`SymbolRange` with symbol
  decoding. An encoder must interleave raw bits and coded symbols in one range
  coder — it is not possible to emit literals "outside" the arithmetic stream.
- Gate: a round-trip unit test (our writer → our reader) plus dav2d on the final
  stream. A round-trip alone can hide a shared misunderstanding, so dav2d is the
  authority.

## 1. Bit-level conventions

| Concept | Spec | Notes |
|---|---|---|
| `f(n)` | §4.11.2, §8.1 | MSB-first, unsigned, n bits |
| `uvlc()` | §4.11.3 | leadingZeros zeros, then 1, then `leadingZeros` bits of `v - (1<<lz) + 1`; `v=0` → `1` |
| `le(n)` | §4.11.5 | unsigned little-endian, n whole bytes |
| `leb128()` | §4.11.6 | 7 bits per byte, MSB = continuation |
| `ns(n)` | §4.11.8 | non-symmetric range 0..n-1; `ns(3)`: 0→`0`, 1→`10`, 2→`11` |
| `S()` | §8.3 | arithmetic-coded symbol using the CDF selected in §8.3.2 |
| `L(n)` | §4.11.11, §8.2.5 | `n` raw equiprobable bits through the range coder |
| `byte_alignment()` | §5.2.4 | **zero bits only**, until bit position is a multiple of 8 |
| `trailing_bits(n)` | §5.2.3 | one `1` bit then zeros |

All bit positions are MSB-first within each byte.

## 2. Stream layout

### 2.1 OBU sequence

Minimum legal order for a still picture (§7.3, §7.3.3):

```
OBU_TEMPORAL_DELIMITER   (optional but conventional; sets FirstPictureInTU = 1)
OBU_SEQUENCE_HEADER
OBU_CLOSED_LOOP_KEY      (contains frame_header + tile group payload)
```

- `OBU_TEMPORAL_DELIMITER` is an empty payload (§5.5). If omitted, the first
  `OBU_CLOSED_LOOP_KEY` still works: `startCVS = obu_type == OBU_CLOSED_LOOP_KEY &&
  FirstPictureInTU` (§5.18.2), and `FirstPictureInTU` is 1 at the start of a
  temporal unit because `open_bitstream_unit()` for a TD sets it (§5.2.1). If you
  omit the TD, `FirstPictureInTU` is whatever the previous TU left; for a
  single-frame stream put the TD in. **Use the TD.**
- Exactly one frame is allowed because the sequence header has
  `single_picture_header_flag = 1` and `still_picture = 1` (§5.4.1, §6.4.1).

### 2.2 OBU frame

`open_bitstream_unit(sz)` (§5.2.1) with length-delimited framing (Annex B):

```
leb128() num_bytes_in_obu
open_bitstream_unit(num_bytes_in_obu)
```

`obu_header()` (§5.2.2):

```
obu_header_extension_flag  f(1)   # 0 for us
obu_type                   f(5)
obu_tlayer_id              f(2)   # 0
obu_mlayer_id              f(3)   # only if extension flag
obu_xlayer_id              f(5)   # only if extension flag
```

With extension flag 0: `obu_mlayer_id = 0` and
`obu_xlayer_id = (obu_type == OBU_MSDO || obu_type == OBU_TEMPORAL_DELIMITER) ?
GLOBAL_XLAYER_ID : 0` (§5.2.2). So a TD gets `GLOBAL_XLAYER_ID` inferred; all our
other OBUs get 0. `OBU_SEQUENCE_HEADER` is **not** layer-specific but still infers
`obu_xlayer_id = 0` when the extension flag is 0 — which is what `load_xlayer_context`
expects.

`obuPayloadSize = sz - 1 - obu_header_extension_flag` (§5.2.1).

OBU type values used (§6.2.2): `OBU_SEQUENCE_HEADER = 1`,
`OBU_TEMPORAL_DELIMITER = 2`, `OBU_CLOSED_LOOP_KEY = 4`.

Header byte for our three OBUs:

| OBU | extension | type | header bits | first byte |
|---|---|---|---|---|
| TD | 0 | 2 | `0 00010 00` | `0x10` |
| SEQ | 0 | 1 | `0 00001 00` | `0x08` |
| CLK | 0 | 4 | `0 00100 00` | `0x20` |

(The low 2 bits are `obu_tlayer_id = 0`.)

Non-tile OBUs must end with `trailing_bits(remainingPayloadBits)` (§5.2.1), i.e. a
single 1 bit then zero padding to the byte boundary. The sequence-header OBU
therefore ends `...0 1` padded with zeros.

The tile-group OBU does **not** get `trailing_bits` from `open_bitstream_unit`:
`usedArith = is_tile_group()` and the whole payload is consumed by the tile group
(§5.2.1). Its trailing bits are the ones `exit_symbol()` consumes inside the last
tile (§8.2.4).

### 2.3 IVF wrapper

IVF is not part of the AV2 spec. Layout used by dav1d/dav2d-style CLIs:

```
file header, 32 bytes:
  'D','K','I','F'          4
  version = 0              u16 LE
  header_size = 32         u16 LE
  fourcc                  4 bytes   ('AV02'; confirmed with the pinned dav2d)
  width                    u16 LE
  height                   u16 LE
  timebase_den             u32 LE
  timebase_num             u32 LE
  frame_count              u32 LE
  unused                   u32 LE
per frame:
  frame_size               u32 LE
  timestamp                u64 LE (0)
  payload                  frame_size bytes (one temporal unit)
```

The pinned dav2d decoded `testdata/sample_480x270_130f.ivf` (fourcc `AV02`), so
write `AV02`. See `docs/open-questions.md` §C2.

Notes:

- **`bit_depth_idc` is inverted**: 0 = 10-bit, 1 = 8-bit (§6.4.1 table). Writing 0
  gives a 10-bit stream.
- `seq_level_idx` must be 0..31; 31 means "maximum parameters" (§A.4). Level 5.1
  (index 7) is comfortably above 64x64/256x256 and avoids any level edge cases.
  If you use 31, §A.4 says decoders should examine the bitstream themselves; some
  decoders may be stricter. **Use 7.**
- `MaxQ = MAXQ_8_BITS = 255` for 8-bit (§6.4.1, §9 constants).
- `frame_width_bits_minus_1` must cover `max_frame_width_minus_1`:
  `n = frame_width_bits_minus_1 + 1`. For 256, `n = 8` → value 7. You may also use
  7 for a 64-wide stream; only the frame header uses these widths.
- With `equal_ac_dc_q = 1` the three `base_*_delta_q` reads collapse to just
  `base_uv_ac_delta_q`; `BaseUVDcDeltaQ = BaseUVAcDeltaQ`.
  `DELTA_DCQUANT_BITS = 5`, `DELTA_DCQUANT_MAX = 8`, `DELTA_DCQUANT_MIN = -23`
  (§9 constants), so **23** encodes zero.
- `enable_sdp = 0` is essential: with SDP the 64x64 intra block is coded as separate
  luma and chroma partitions (§5.20.3.1), doubling the partition syntax.
- `enable_ext_partitions = 0` keeps `read_partition()` from coding
  `do_ext_partition` / `do_uneven_4way_partition`.
- `enable_mrls = 0` removes the per-block `mrl_index` symbol.
- `enable_dip = 0` removes `dip_mode_info()`.
- `enable_cfl_intra = 0` removes `is_cfl`, and `uv_mode` uses the 13-mode
  `UV_INTRA_MODES_CFL_NOT_ALLOWED` alphabet.
- `enable_tcq = 0` and `enable_parity_hiding = 0` remove TCQ state and the hidden-DC
  path in `coeffs()`.

## 6. Tile payload — block layer

`decode_tile()` §5.20.2.1 for 64x64 (one SB, `MiRows = MiCols = 16`):

```
clear_above_context()
for r = MiRowStart (0) .. < MiRowEnd (16) step 16:      # one SB row
    clear_left_context()
    for c = MiColStart (0) .. < MiColEnd (16) step 16:  # one SB
        decode_partition(r, c, BLOCK_64X64, BLOCK_INVALID, 0, 1, 0)
```

### 6.1 Partition decisions

`read_partition()` §5.20.3.2. For our settings (`enable_sdp = 0`,
`enable_ext_partitions = 0`, `enable_uneven_4way_partitions = 0`,
`MaxPbAspectRatio = 8`, `FrameIsIntra = 1`):

**(a) 64x64 block at (0,0)** — `partition_implied()` returns not-implied
(`partition_implied_at_boundary` sees room in both directions), and
`init_allowed_partitions()` allows NONE and SPLIT, so:

| # | Symbol | Value | CDF | Context |
|---|---|---|---|---|
| 1 | `do_split` | 1 | `TileDoSplitCdf[0][ctx]` | `ctx = 12` |
| 2 | `do_square_split` | 1 | `TileDoSquareSplitCdf[0][ctx]` | `ctx = 0` |

`do_split` context: `Partition_Size_Adjust[BLOCK_64X64] = 3` → `3*4 = 12`;
`ctx1 = Mi_Height_Log2[LeftMiSizes[0][0]] < bsh` → `6 < 4` false;
`ctx2` likewise false. `do_square_split` context: `left = above = 0` (no
neighbours inside the tile) and `bSize != BLOCK_256X256` → `0`.
(This encodes `PARTITION_SPLIT`.)

**(b) four 32x32 blocks** at (0,0), (0,8), (8,0), (8,8) — `partition_implied()`
is not implied for `BLOCK_32X32` (only `bSize == BLOCK_4X4 || bSize >= BLOCK_4X32`
is auto-NONE, and `BLOCK_32X32` is enum 9, below `BLOCK_4X32` = 25). Each codes:

| # | Symbol | Value | CDF | Context |
|---|---|---|---|---|
| 1 | `do_split` | 0 | `TileDoSplitCdf[0][ctx]` | 8 / 10 / 9 / 11 |
| → | `PARTITION_NONE` | | | |

Contexts for `BLOCK_32X32`: `Partition_Size_Adjust[BLOCK_32X32] = 2` → base 8;
`ctx1 = (Mi_Height_Log2[left neighbour] < 5)`, `ctx2 = (Mi_Width_Log2[above neighbour] < 5)`.
`LeftMiSizes`/`AboveMiSizes` are `BLOCK_256X256` (log2 6) outside the block:

| block | ctx1 | ctx2 | ctx |
|---|---|---|---|
| (0,0) | 0 | 0 | 8 |
| (0,8) | 1 (left is 32x32) | 0 | 10 |
| (8,0) | 0 | 1 (above is 32x32) | 9 |
| (8,8) | 1 | 1 | 11 |

| 8 | `y_mode_set` | always | **0** | `S()` |
| 9 | `y_mode_index` | `y_mode_set == 0` | **0** | `S()` |
| 10 | `uv_mode` | `HasChroma`, `cflAllowed = 0` | **0** | `S()` |
| 11 | palette | `allow_screen_content_tools = 0` | not coded | 0 |
| 12 | `dip_mode_info` | `enable_dip = 0` | not coded | 0 |

`y_mode_set = 0, y_mode_index = 0` → `modeIdx = 0 < NON_DIRECTIONAL_MODES_COUNT (5)`
→ `YMode = Reordered_Y_Mode[0] = DC_PRED (0)` (§5.20.5.5).
`uv_mode = 0` → `get_intra_uv_mode_set(0)`; `YMode = DC_PRED` is not directional, so
`UVMode = Default_Mode_List_Uv[0] = DC_PRED` (§5.20.5.6).

CDF contexts:

| Symbol | CDF | Context | Why |
|---|---|---|---|
| `y_mode_set` | `TileYModeSetCdf` | — | `Default_Y_Mode_Set_Cdf[5]` = 4 symbols |
| `y_mode_index` | `TileYModeIndexCdf[ctx]` | 0 | `ctx = (jointModeAboveLeft>=5)+(jointModeAboveRight>=5)`; both DC (0) |
| `uv_mode` | `TileUVModeCflNotAllowedCdf[ctx]` | 0 | `ctx = is_directional_mode(DC_PRED) = 0` |

`IntraJointMode` is 0 for every block, so `y_mode_index`'s context is always 0.

### 6.3 Transform size

`read_block_tx_size()` §5.20.6.2. `TxMode = TX_MODE_LARGEST` (from
`tx_mode_select = 0`) → `read_tx_size()` returns 0 without reading
`tx_do_partition` (§5.20.6.1). `TxSize = Max_Tx_Size_Rect[BLOCK_32X32] = TX_32X32`
for luma; chroma gets `Max_Tx_Size_Rect[get_plane_residual_size(BLOCK_32X32, 1)] =
Max_Tx_Size_Rect[BLOCK_16X16] = TX_16X16` (§5.20.7.25).

No transform-partition syntax at all.

### 6.4 Prediction

`make_intra_prediction()` (§5.20.7.24) → `predict_intra()` (§7.13.2.1).

- For the **first** block in the frame (0,0) with 32x32 DC: `haveAbove = haveLeft = 0`
  → `pred[i][j] = 1 << (BitDepth-1) = 128` (§7.13.2.10).
- For later blocks: DC = average of the available top row and left column
  (`approx_divide(sum, w+h)`, `Clip1`).
- `numAboveRight`/`numBelowLeft` only matter for directional modes and DIP;
  `allowCorners = 1` for our blocks because `LumaTxMiddle = 0`, but DC ignores them.
- Chroma 16x16 uses `UVMode = DC_PRED`; `largeChroma = 0` (w,h ≤ 32) so the
  non-subsampled DC process applies.

### 6.5 Residual and coefficients

`residual()` §5.20.7.23 → `transform_block()` §5.20.7.24 → `coeffs()` §5.20.7.27.

For a 32x32 block: `widthChunks = heightChunks = 1`, so:
- plane 0: one `transform_block(0, 0,0, TX_32X32, 0,0, allowCorners=1, ...)`.
- planes 1,2: `ChromaMiSize = BLOCK_32X32`, `planeSz = BLOCK_16X16`,
  `txSz = TX_16X16`, one block per plane.

`coeffs()` for luma 32x32 (`txSzCtx = (Tx_Size_Sqr[TX_32X32] + Tx_Size_Sqr_Up[TX_32X32] + 1) >> 1 = 3`,
`segEob = 32*32 = 1024`):

| # | Element | Value for DC-only block | CDF |
|---|---|---|---|
| 1 | `all_zero` | **0** | `TileTxbSkipCdf[is_inter||fsc_mode=0][3][ctx]` |
| 2 | `eob_pt_1024` | **0** (→ `eobPt = 1`, `eob = 1`) | `TileEobPt1024Cdf[eobCtx=0]` |
| — | `eob_extra` | not coded (`eobPt < 3`) | — |
| — | `transform_type()` | `!is_inter && eob == 1` → `DCT_DCT`, **no bits** | §5.20.8.2 |
| 3 | `coeff_base_eob` | level 1 → symbol **0** | `TileCoeffBaseEobCdf[3][ctx=0]` |
| — | `coeff_br` | not coded (level 1 ≤ `LF_NUM_BASE_LEVELS = 4`) | — |
| 4 | `dc_sign` | sign bit | `TileDcSignCdf[ptype=0][isHidden=0][ctx]` |

`all_zero` context for plane 0, `txSz = 32x32`, `bsize = 32x32`:
`bw == w && bh == h` → `ctx = 0`. (For chroma the derivation takes the `plane > 0` branch:
`ctx = (above!=0) + (left!=0)`, then plane 1 adds `+6`, while plane 2 adds `+3`
if the chroma residual block is larger than the transform block and `+6` if
`EobU != 0`. So plane 1 is 6..8 and plane 2 is 0..11 → `V_TXB_SKIP_CONTEXTS = 12`.)

`coeff_base_eob` context: `c == 0` → `ctx = SIG_COEF_CONTEXTS_EOB - 4 = 0`.
`dc_sign` context: 0 for the first block (no above/left DC contexts);
1 or 2 when neighbours have DC signs.

`read_quant()` (§5.20.7.28) is skipped when `level < maxLevel`; for luma LF
`maxLevel = LF_NUM_BASE_LEVELS + COEFF_BASE_RANGE + 1 = 8`, so |DC| ≤ 7 needs no
extension bits. Same for AC: `maxLevel = NUM_BASE_LEVELS + COEFF_BASE_RANGE + 1 = 6`
for HF luma, 5 for chroma.

**Chroma 16x16** (`txSzCtx = 2`, `eobMultisize = 4`):

| # | Element | Value | CDF |
|---|---|---|---|
| 1 | `all_zero` | 0 | plane 1: `TileTxbSkipCdf[0][2][ctx]`; plane 2: `TileVTxbSkipCdf[ctx]` |
| 2 | `eob_pt_256` | 0 | `TileEobPt256Cdf[eobCtx=2]` |
| 3 | `intra_tx_type` | **0** (= DCT_DCT) | `TileIntraTxTypeSet1Cdf[Tx_Size_Sqr[TX_16X16]=2]` |
| 4 | `coeff_base_eob` | 0 | `TileCoeffBaseEobUvCdf[2][0]` |
| 5 | sign | raw `L(1)` bit | — |

⚠️ **Chroma always codes `intra_tx_type`.** `get_tx_set(TX_16X16, 0)` returns
`TX_SET_INTRA_1 = 5` (>0) for intra, so `transform_type()` reads one symbol
(§5.20.8.2, §5.20.8.3). `Md_Idx_To_Type[Size_Class[TX_16X16]=2][DC_PRED=0][0] = 0 =
DCT_DCT`, so the value is always 0. Luma 32x32 returns `TX_SET_DCTONLY = 0` and codes
nothing.

Sign coding (§5.20.7.27): the luma DC sign is `S() dc_sign`; every other sign
(including chroma DC and all AC) is a raw `L(1)` bit. That asymmetry is normative.

If you want **all-zero residual** blocks (e.g. flat source), set `all_zero = 1` and
nothing else is coded for that transform block — `coeffs()` returns 0 and
`transform_block()` skips dequant/reconstruct.

## 7. Reconstruction (encoder must match bit-exactly next)

Decoder path, needed for the encoder's own reconstruction loop:

1. `dequant()` §7.14.4:
   - `tw = th = 32`, `pels = 1024`, `shift = 1`, `dqDenom = 2` (luma);
     chroma 16x16: `pels = 256`, `shift = 0`, `dqDenom = 1`.
   - `q = get_dc_quant(plane)` at (0,0), else `get_ac_quant(plane)`.
   - `dqHigh = |qc| * q`; `dq = Round2(dqHigh & 0xFFFFFF, QUANT_TABLE_BITS=3)`;
     `Dequant = Clip3(-(1<<(7+8)), (1<<(7+8))-1, sign * (dq / dqDenom))`.
2. 2D inverse transform §7.15.4 / §7.15.4.1:
   - `Transform_Shift[TX_32X32] = {6, 13}` (row, col); `TX_16X16 = {6, 13}` too.
   - Row pass: `1d_transform(txRowIn, DCT, w, rowShift=6, colTx=0)` →
     clip to `±(1 << (8+7))`; store `intermediate[i][j]`.
   - Column pass: `1d_transform(txColIn, DCT, h, colShift=13, colTx=1)` →
     clip to `±(1 << 8)`.
   - `Abs(log2W-log2H)` is even for square sizes → **no 2896 scaling**.
3. `1d_transform` §7.15.2.1 uses `Dct_Kernel{N}[j][i] * src[j]`, i.e. the
   **transpose** of the matrix as printed (`Dct_Kernel32[j][i]`, j = input index).
   `result[i] = Clip3(..., Round2(sum, shift))`.
4. `reconstruct()` §7.14.3: `CurrFrame = pred + Residual`, `Clip1`.

`Dct_Kernel32` is in `spec/tables/dct_kernels.json` and `spec/tables/dct32.h`.

## 8. Quantisation

- `base_q_idx` 0..255. **0 is lossless** and changes everything (`CodedLossless = 1`
  → `TxMode = ONLY_4X4`, WHT, no deblocking syntax). M0 must use `base_q_idx >= 1`.
- `get_q(qindex, delta)` §7.14.2:
  ```
  if (qindex == 0 && delta <= 0) return Ac_Qlookup[0];       # 64
  qClamped = Clip3(1, MaxQ, qindex + delta)
  return qlookup(qClamped)   # q<25: Ac_Qlookup[q]; else Ac_Qlookup[((q-1)%24)+1] << ((q-1)/24)
  ```
- Luma: DC uses `DeltaQYDc + BaseYDcDeltaQ = 0`; AC uses delta 0. Chroma: DC uses
  `DeltaQUDc + BaseUVDcDeltaQ = 0`; AC `DeltaQUAc + BaseUVAcDeltaQ = 0`. So both
  planes use `get_q(base_q_idx, 0)`.
- Table: `spec/tables/quant.json` (`qlookup_q0_255`). `base_q_idx = 0` → 64,
  `25` → 80, `50` → 164, `90` → 528, `120` → 1248, `200` → 12544, `255` → 61440.

The dequantiser multiplies by the *step*, then `Round2(... & 0xFFFFFF, 3)` — the
`& 0xFFFFFF` is a 24-bit mask, not a rounding trick; with 8-bit coefficients and
`q ≤ ~2000` the product stays below 2^24 for |qc| < ~8000, but do not assume.

## 9. 256x256 variant

Everything above is identical except:

| Item | 64x64 | 256x256 |
|---|---|---|
| `max_frame_width_minus_1` / height | 63 | 255 |
| `frame_width_bits_minus_1` / height | 5 | **7** (8-bit fields) |
| `MiCols`, `MiRows` | 16, 16 | 64, 64 |
| superblocks | 1 | 16 (4x4) |
| `decode_tile` outer loops | 1 SB | 4x4 SBs |
| partition bins | 1× (`1,1`) + 4× (`0`) | 16× (`1,1`) + 64× (`0`) |
| `all_zero` ctx for luma | 0 always | **0 always** (tx 32x32 == block 32x32 → the `bw==w && bh==h` branch) |

The 256x256 frame has 16 superblocks. `LeftMiSizes` / `AboveMiSizes` persist across
SBs (only reset per SB *row* / per tile), so `do_split` and `all_zero` contexts vary
across the frame. See §5.20.5 / §8.3.2 for the derivations; `docs/tiles.md` has the
tile-boundary rules.

For 256x256 the tile grid is 4x4 SBs, so `increment_tile_cols_log2` /
`increment_tile_rows_log2` *can* be coded — but M0 keeps one tile and writes
`uniform_tile_spacing_flag = 1` followed by nothing (min = max = 0), exactly as for
64x64.

## 10. Order-of-bits summary (64x64)

```
IVF header (32 B)

OBU 1: TD
  leb128(1)                      0x01
  header 0x10
OBU 2: SEQ
  leb128(12)                     0x0c   (1-byte header + 11-byte payload)
  header 0x08
  8 bytes of sequence header bits (see §3), last byte ends with the trailing 1 bit
OBU 3: CLK
  leb128(n)
  header 0x20
  is_first_tile_group = 1               1 bit
  frame header                          22 bits
  byte_alignment                        2 zero bits
  ---- byte aligned ----
  tile payload:
    range-coded symbols, then exit_symbol padding (1 + zeros)
    the last byte(s) are the OBU trailing bits
```

`n` = 1 (OBU header) + 3 (tile-group bit + frame header + alignment) + tile bytes.

## 11. dav2d compatibility

Target decoder: **dav2d, pinned at `f9dafbc`** (AV2 v1.0.0-era nightly, 2026-11-10).
dav2d is a dav1d-derived C decoder; it is a black box here. Nothing below was
verified by reading its source.

### 11.1 Choices that are safe by construction

These are the mainstream, non-exotic paths and match what a v1.0.0 decoder must
support:

| Choice | Why it is safe |
|---|---|
| 8-bit 4:2:0 (`bit_depth_idc = 1`, `chroma_format_idc = 0`) | Main profile, the primary conformance configuration (Annex A.2) |
| One tile | no cross-tile state; dav2d's tile support is reported to cover 1x1..8x2, but 1x1 is the baseline |
| `OBU_CLOSED_LOOP_KEY` key frame, `single_picture_header_flag = 1` | explicit still-picture path in the spec (§5.4.1) |
| DC intra (`YMode = UVMode = 0`) | the simplest intra mode, no edge filtering, no MRL, no DIP |
| DCT 32x32 luma, DCT 16x16 chroma | `TX_SET_DCTONLY` / `TX_SET_INTRA_1` with `intra_tx_type = 0` |
| `tx_mode_select = 0` (TX_MODE_LARGEST) | no transform partitioning |
| No segmentation, delta-Q, QM, CCTX, TCQ, parity hiding, FSC, IST | all disabled at sequence/frame level |
| No CDEF/GDF/CCSO/loop restoration/deblocking | all disabled at sequence level, so zero filter syntax |
| No film grain | `film_grain_params_present = 0` |
| No palette / CfL / intrabc / SBC / MHCCP / IBP | disabled at sequence level and/or `allow_screen_content_tools = 0` |

### 11.2 Optional AV2 features to avoid until tested against dav2d

Do not turn these on before the basic stream decodes cleanly:

1. **`single_picture_header_flag = 0`.** It re-enables `seq_tier`,
   `decoder_model_info`, layer maps, screen-content syntax, `enable_inter_ddt`,
   `choose_tcq_per_frame`, `cdef_on_skip_txfm` bits, and `context_update_tile_id`
   in `tile_info()`. More surface, no benefit for a still.
2. **`seq_level_idx = 31`.** Legal ("maximum parameters", §A.4) but some decoders
   enforce level tables anyway. Use a real level (7 = 5.1).
3. **`TxMode = TX_MODE_SELECT` + transform partitioning.** Adds `tx_do_partition`,
   `tx_partition_type`, `tx_2or3_partition_type` and mid-block `txSz` bookkeeping;
   the `allowCorners`/`LumaTxMiddle` interaction for intra is easy to get wrong.
4. **`enable_parity_hiding = 1`.** Requires the hidden-DC reconstruction
   (`quant = 2*quant + sumAbs1`) and changes `maxLevel`; high risk, low gain at M0.
5. **`enable_tcq = 1`.** Changes coefficient magnitude mapping and the dequant
   shift (`shift += 1` when `allow_tcq && plane == 0 && 2D`).
6. **`enable_fsc = 1`.** A completely different coefficient scan/EOB order
   (`coeff_base_bob`, `coeff_base_idtx`, `idtx_sign`, forward scan).
7. **`enable_cctx = 1`.** Adds `cctx_type` and the U/V joint dequant matrix.
8. **`enable_chroma_dctonly = 1`.** Switches chroma to `TX_SET_INTRA_2`; harmless in
   principle but untested against dav2d at M0.
9. **`enable_mrls`, `enable_dip`, `enable_ibp`, `enable_mhccp`, `enable_cfl_intra`.**
   Each adds per-block symbols and prediction paths; all are orthogonal to M0.
10. **`enable_sdp = 1` / `enable_ext_partitions = 1`.** New AV2 partitioning; the
    SDP luma/chroma tree split is the most intricate part of §5.20.3.1.
11. **`use_256x256_superblock = 1` / `use_128x128_superblock = 1`.** Larger SBs
    change `SbSize`, `read_lr` units, GDF/CCSO unit sizing, and `do_split` contexts.
12. **`reduce_pb_aspect_ratio = 1`**, segmentation, `enable_ext_seg`.
13. **`still_picture = 0` with multiple frames.** Requires order hints, reference
    refresh, CDF averaging across frames (`frame_end_update_cdf`, §7.5), and output
    order handling.
14. **`disable_cdf_update = 0` vs `1`.** Both legal; keep 1 as a debug build flag,
    but ship 0 so the stream exercises the normal adaptive path.

### 11.3 Spec features dav2d may not implement — TODO, do not assume

These are flagged because they are either new in AV2 v1.0.0 or known to be unevenly
implemented across decoders. **None are in the M0 path.** Verify with
`tools/validate_dav2d.sh` before enabling:

- **Multi-tile layouts**: reported to work for 1x1, 2x1, 2x2, 4x2, 8x2 at
  `f9dafbc`, but not verified here. TODO.
- **`disable_loopfilters_across_tiles = 1` with filters on**: one public port notes
  dav2d ignores this in some paths. M0 has no filters, so irrelevant now.
- **`context_update_tile_id` / `avg_cdf_type = 0`**: only reachable with
  `single_picture_header_flag = 0`. TODO if we ever leave still-picture mode.
- **GDF (`enable_gdf`)**, **CCSO (`enable_ccso`)**, **PC-Wiener / non-separable
  Wiener**, **flexible restoration types**: AV2-only tools with no AV1 ancestry.
- **TIP frames**, **BRU**, **RAS**, **SEF**, **MSDO/LCR/Atlas**: multistream or
  inter-only machinery, out of scope.
- **`use_256x256_superblock`**, **SDP**, **extended partitions**, **DIP**, **MHCCP**,
  **IBP**, **MRL secondary**, **FSC**, **TCQ**, **CCTX**, **IST/DDT**: AV2-only
  coding tools. Marked TODO until a vector passes.
- **10-bit / 4:2:2 / 4:4:4 / monochrome**: 8-bit 4:2:0 is the only M0 target. 10-bit
  is reported bit-exact in public ports; the others are less exercised.
- **Level 31 streams**: legal per §A.4, decoder behaviour is "examine the
  bitstream"; do not rely on it.

### 11.4 Validation command

```
tools/validate_dav2d.sh out.ivf
tools/validate_dav2d.sh out.ivf source.y4m     # with PSNR
```

The script (see `docs/validation.md` for the pin and policy) resolves `dav2d`
from `$DAV2D`, `tools/bin/dav2d`, or `tools/bin/dav2d-macos`, then runs the
dav1d-compatible CLI:

```
dav2d -q -i out.ivf -o decoded.y4m --threads 0
```

Confirmed working against the pinned build (`f9dafbc`) with
`testdata/sample_480x270_130f.ivf`; the output is:

```
ivf:     480x270, 130 frame(s), fourcc AV02
decoder: f9dafbc
width=480
height=270
pix_fmt=yuv420p
nb_read_frames=130
OK: dav2d decoded testdata/sample_480x270_130f.ivf
```

Optional: `EXPECTED_MD5=<md5>` re-decodes with `--muxer md5 -o -` and fails on
mismatch; `KEEP=1` copies the decoded Y4M to `./decoded.y4m`; `DAV2D_ARGS`
replaces the decode arguments entirely.

Expected result for a valid M0 stream: exit 0, one 64x64 (or 256x256) 4:2:0 frame,
and PSNR close to the quantiser's noise floor (a few dB below the source's
self-PSNR; with `base_q_idx = 90` expect roughly 30–35 dB on natural content).

## 13. Uncertainties in this document

- **`TileTxbSkipCdf` indexing**: §8.3.2 writes
  `TileTxbSkipCdf[is_inter||fsc_mode][txSzCtx][ctx]` (3 indices) for a declared
  5-D array `[COEFF_CDF_Q_CTXS][2][TX_SIZES][TXB_SKIP_CONTEXTS][3]`. The only
  consistent reading is that `init_coeff_cdfs()` selects the `idx` slice once
  (`base_q_idx ≤ 90 → 0`, `≤140 → 1`, `≤190 → 2`, else 3) and the frame-level
  array has 4 dims. Same for every other coefficient CDF. Flagged in
  `docs/open-questions.md`.
- **Chroma `intra_tx_type`** is required (see §6.5). If a first stream fails on
  chroma only, this is the first thing to check.
- **`base_q_idx` and `qctx`**: for `base_q_idx = 90` the coeff context index is 0;
  91 jumps to 1, which selects a different default CDF set. Pick 90 exactly for
  the first test to use the first slice.
- **dav2d CLI**: confirmed (`dav2d -q -i in.ivf -o out.y4m --threads 0`,
  `--muxer md5`), see §11.4.
- **IVF fourcc**: confirmed `AV02` against the pinned build's sample.
- **`le(TileSizeBytes)`**: not used at 1 tile, but `docs/tiles.md` relies on it.
- **`decode_frame_wrapup()`** (§7.2) is invoked after the last tile group; it does
  output/refresh bookkeeping and does not read bits. Confirm on first integration.
