# Negative results and do-not-repeat

Read this before proposing an implementation. Repeating a listed approach is a
waste of time unless you have new measured evidence.

Status legend:

- **CONFIRMED** — measured or directly observed
- **DEFERRED** — deliberately out of scope for now
- **OPEN** — not yet measured; do not cite as a result

## Bitstream / encoder

| Status | Do not do | Why | Do instead |
|---|---|---|---|
| CONFIRMED | Use `src/entropy/range_coder.*` for the AV2 stream | It is a generic arithmetic coder, not the normative §8.2 state machine; it cannot produce AV2-decodable bytes | Use `src/entropy/av2/` |
| CONFIRMED | Pad 640x360 to 640x384 | Product owner rejected padding; exact 640x360 is now supported | Encode exact dimensions; use edge partition handling |
| CONFIRMED | Use `PARTITION_VERT` at a bottom-edge superblock | `dav2d` returns `Error decoding frame: Invalid argument`; VERT is not allowed when `has_rows` is false | Use `PARTITION_NONE` at the 64x64 SB for the 640x360 bottom edge; 32x16/32x8 implied paths for narrower edges |
| CONFIRMED | Use `PARTITION_SPLIT` at 64x64 or below | AV2 v1.0.0 `Partition_Subsize` defines SPLIT only for 128→64 and 256→128; it is illegal at 64 and below | Use `HORZ`/`VERT` (the M0 rect tree) for 32x32 quadrants; do not "fix" it into SPLIT |
| CONFIRMED | Compute `MiCols`/`MiRows` as `ceil(width/4)` | Spec is `2 * ((dimension + 7) >> 3)`, which differs for non-multiple-of-8 sizes | Use the spec formula |
| CONFIRMED | Hand-type CDF, scan, DCT, or quant tables | Error-prone and already generated | Use `spec/tables/` and `src/encoder/generate_*.py` |
| CONFIRMED | Enable adaptive CDFs by default | It changes pinned MD5s | Keep `disable_cdf_update=1`; opt in with `--adaptive-cdf` |
| CONFIRMED | Copy AVM/SVT/clave/av2-turbo encoder code | Project constraint is spec-only | Implement from the spec; use decoders as black boxes |
| CONFIRMED | Emit a multi-frame header (MFH) in the single-picture still path | The pinned dav2d `f9dafbc` does not apply MFH state there: `--still --still-mfh` on 64x64 fails with `Error decoding frame: Invalid argument`; at 640x360 it decodes but skips deblocking (1,472 samples differ from `--still`, max 2), i.e. the MFH `deblocking_filter_update` bits are ignored; an MFH with the update flag clear fails at every size | Keep MFH off the still CLI. Wire `src/frame/mfh` only on a non-single-picture (M2) stream, where `mfh_gate` proves it. Reproducer: encode `tests/data/basic_{64x64,640x360}_1f.y4m` with `--still --still-mfh` and decode with `tools/validate_dav2d.sh` |
| DEFERRED | Inter frames, loop filters, RDO, rate control | M0 is still-picture only | Finish the CUDA M0 path first |
| CONFIRMED | Ship `--video-refmvbank` (`enable_refmvbank = 1`) as a product flag | The §7.12.2.21 bank agrees with pinned dav2d `f9dafbc` for one superblock row (64x64, 128x64 and 64x128 decode exactly), but the first bank-selected block in the **third** superblock row decodes with a different MV. Repro: the synthetic moving 64x192 clip, frame 1, block `(MiRow, MiCol) = (32, 8)` (`--video --frames 8 --video-refmvbank`); 211 luma samples differ. Per-row clear, no clear, per-SB clear, seeded and unseeded variants all fail, so the residual is not the `clear_left_context` policy alone | Keep the tool rejected by name (`--video-refmvbank` errors out); the implementation is retained behind the rejection for a future investigation |
| CONFIRMED | Use `--video-mv-traj` with `NumTotalRefs == 3` | `--video-refs 2 --video-ref-mvs --video-mv-traj` is sample-exact at 64x64/128x128/640x360, but the three-reference 640x360 stream differs in one 16x16 leaf (frame 3, MI `(68,64)`, 211 luma samples) | Gate the tool at two references; reject `--video-mv-traj --video-refs 3` by name |

| CONFIRMED | Skip luma directional IDIF | The decoder applies it; prediction will mismatch | Implement the exact §7.13.2 IDIF path |
| CONFIRMED | Filter intra edge samples in place | Later taps read already-filtered values; CPU/CUDA parity differed by 244k samples | Snapshot the row, write filtered values into a copy/row per §7.13.2.18 |
| CONFIRMED | Read edge samples outside the visible plane | Wrong prediction and out-of-bounds reads | Clamp to `max_x`/`max_y` and pass the padded stride |
| OPEN | Claim intra-mode gains before integration | The component emits no bitstream | Wire it, pass `dav2d`, then measure |
| CONFIRMED | Expect `--video-intra-full` to improve RD at QP 90 | Measured on a 120-frame 640x360 clip (RTX 3060, QP 90): 1,254,794 B / 41.001 dB PSNR-Y default vs 1,316,505 B / 40.985 dB with the 61-candidate search (+4.9% rate, −0.016 dB). The intra/inter decision is SSE-only, so better intra SSE selects more intra leaves (19,407 vs 18,271) without paying their rate | Keep `--video-intra-full` opt-in; add a rate-aware intra/inter decision before enabling it by default |
| CONFIRMED | Use the "raster order → `num4_below_left = 0`" shortcut for the video intra availability | Below-left *is* available inside a superblock when the left neighbour is taller (e.g. a 16-tall leaf beside a 32-tall one); the decoder's §6.19.2.3 `BlockDecoded` map reports it, and directional modes then predicted from stale samples (190k luma diffs vs `dav2d`). Above-right is likewise capped at the superblock edge for interior rows | Replay `clear_block_decoded_flags()` per superblock and derive the counts with the still encoder's `count_top_right`/`count_bottom_left` rules (`src/pipeline/video/video_intra_search.h`) |

Remaining blockers for this surface (all rejected by name, not silent):

- The pinned `dav2d` skips AV2 metadata OBUs and type 15; it proves decode
  invariance only. `avmdec` is the parser gate, and the two conclusions must be
  quoted together.
- `--metadata-frame-hash` is wired on the still/basic/lossless writers only.
  `--video`, `--tiles`, `--svc-layers` and the `--bit-depth`/`--chroma` format
  writers reject it because they have no per-unit metadata carrier.
- All `--metadata-*` flags and `--video-brt` are rejected by the format
  (10-bit / non-4:2:0) and `--svc-layers` writers, which own separate unit
  assembly.
- `--video-brt` emits the neutral non-dependent `br_time`; it does not run the
  §E.5.4 buffer planner. Schedule/overflow/underflow conformance stays with
  `src/codec/rate/rc/hrd/hrd_buffer.cpp` and its gate.
- The nested §5.4.13 form stays opt-in; do not enable it by default, because
  `dav2d f9dafbc` cannot parse the sequence header.
